# 岗位专项：对话任务、微调与部署

以下来自岗位要求与通用技术准备，不是已确认的笔试题。

## 1. 对话任务

- **意图识别**：识别用户想做什么，例如“打开客厅灯”的意图是开灯。
- **槽位/实体抽取**：抽取设备=客厅灯、目标亮度等参数；BIO 标签可标记实体片段边界。
- **多轮状态跟踪**：“再调暗一点”需要继承上一轮设备与当前亮度；缺少设备或调节幅度时先澄清，不能猜测后直接执行。
- **问答生成**：评估不仅看文字流畅度，还要看事实、工具调用结果和失败反馈。

**口述题**：“打开客厅灯，随后说‘再调暗一点’。”讲清状态保存、参数校验、权限检查、工具执行、失败重试和对用户的真实反馈。

## 2. 训练与轻量化

- **SFT**：用示范输入输出训练目标行为；对话样本通常只对需要预测的 assistant token 计 loss，padding token 也需 mask，具体规则依任务而定。
- **LoRA**：冻结基础权重，学习低秩更新 `W'=W+(α/r)BA`。原矩阵为 `4096×4096`、秩 `r=8` 时，新增矩阵参数 `8×4096+4096×8=65,536`，不等于总训练显存只需这么多字节。
- **QLoRA**：结合低比特量化的基础权重与 LoRA 训练；仍需要考虑激活、优化器状态、序列长度和吞吐。
- **DPO/RLHF**：了解偏好数据、奖励/偏好目标与 SFT 的关系即可；不应把它们与普通监督微调混为一谈。
- **灾难性遗忘**：专项数据训练后通用能力退化；用混合数据、验证集和回归测试观察。

## 3. RAG、Agent 与部署取舍

- 知识更新频繁、需要来源可追溯：优先考虑 RAG；格式和稳定行为：考虑 SFT/LoRA；二者可以组合。
- Agent 工具调用需校验 schema、权限、超时、重试和幂等性；对外部执行结果不能仅凭模型自述。
- 部署指标至少区分首 token 延迟（TTFT）、每 token 生成速度、端到端延迟、吞吐、并发和显存。Batching 可提高吞吐，但可能增加单请求等待；量化可降低显存，需验证精度与速度变化。

## 检查题

1. 意图识别、槽位抽取和多轮状态跟踪分别解决什么？
2. 为什么 SFT 的 label mask 会影响训练结果？
3. LoRA 减少了哪部分可训练参数？为什么不能据此推断总显存？
4. 高并发时为什么只报告平均延迟不够？
